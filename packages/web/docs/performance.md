# Web performance notes

## Baseline workflow

Run the repeatable baseline harness and build audit from `packages/web`:

```bash
npm run perf:baseline -w @datacenter-tycoon/web
npm run build -w @datacenter-tycoon/web
```

The baseline harness records the key render-path scenarios called out in plan 037:

- start screen load
- first shell render
- active contracts page
- market contracts page
- large datacenter floor grid
- high-speed tick burst
- save/load cycle serialization timings

Build output captures the production asset sizes. `npm run perf:budgets -w @datacenter-tycoon/web` builds the package and checks the current warning budgets against the emitted dist assets.

Interpretation notes:

- Use React Profiler commit counts and actual durations to compare render stability for the scenarios above.
- Treat the high-speed tick burst scenario as the render-frequency baseline for store-driven churn.
- Track save/load serialization cost separately because autosave work happens inside store subscriptions rather than component renders.

## Initial warning budgets

| Metric | Warning budget | How it is checked |
| --- | ---: | --- |
| Largest JS asset (gzip) | 150 kB | `npm run perf:budgets -w @datacenter-tycoon/web` |
| Largest CSS asset (gzip) | 30 kB | `npm run perf:budgets -w @datacenter-tycoon/web` |
| Largest image asset (raw) | 1.10 MB | `npm run perf:budgets -w @datacenter-tycoon/web` |
| Representative save payload | 80 kB | `src/performance/perfBaseline.test.tsx` / save fixture output |
| High-speed tick burst re-render budget | ≤ 3 commits for the harness scenario | `src/performance/perfBaseline.test.tsx` |

These start as warning budgets rather than merge blockers so the team can ratchet them down as the optimisation work lands. `npm run perf:budgets:strict -w @datacenter-tycoon/web` flips the asset checks into hard-fail mode.

### Scenarios to watch during optimisation

| Scenario | Why it matters |
| --- | --- |
| Start screen load | Captures startup render cost and banner asset weight. |
| First shell render | Captures initial shell/layout cost before the player interacts. |
| Active contracts page | Sensitive to selector churn and per-row derivation. |
| Market contracts page | Sensitive to fit summaries, eligible DC filtering, and card child props. |
| Large floor grid | Dense UI surface with the highest DOM count. |
| Save/load cycle | Direct signal for autosave jank and startup/session replacement cost. |
| High-speed tick burst | Detects avoidable subscriber and selector work during monthly updates. |
